# STC8H 多传感器测试工程代码规范

本文件适用于当前四路 TCS3400 与 LZ808-H 压力仪表测试固件。修改代码、协议或 Keil 工程时，必须同时遵守本文件和主协议设计文档。

每次准备新增或修改代码前，必须先读取本文件，再检查 `git status` 和相关模块现有实现；不得只凭上一次对话记忆直接写代码。

当前正式版本为 V1.3。四路 TCS3400 的 ID 与 RGBCIR 读取链路、压力上下限比较和 Y1~Y4 输出已经纳入 `main`；目标通道连续读取和压力单次事务优化已于 2026-07-30 完成实机回归，并通过 PR #6 合并。

## 1. 开发环境

- MCU：STC8H8K64U。
- 编译器：Keil C51 V9.54。
- IDE：µVision V5.37。
- 存储模型：Large。
- 系统时钟：22.1184 MHz 外部晶振，不分频。
- 外部晶振稳定标志超时后不得切换系统时钟；`system_ready=0` 时不初始化或轮询传感器协议。
- UART1：115200 bps、8N1，用于 MTF 上位机协议。
- UART2：115200 bps、8N1，用于 RS485 Modbus RTU。
- Timer0：1 ms 系统时基。

## 2. 工程层级

```text
User
  ↓
App
  ↓
Control
  ↓
Hardware
  ↓
System
```

`Public` 保存所有层都可以使用的公共类型和配置，不包含业务实现。

- `User`：程序入口、初始化顺序和主循环。
- `App`：UART1 组帧、MTF 格式校验、请求提交和返回帧发送。
- `Control`：AB 指令码分发、参数校验、TCS3400 与压力业务状态机。
- `Hardware`：软件 I2C、TCS3400 寄存器、Modbus RTU、压力仪表寄存器语义及板级功能模块。
- `System`：时钟、GPIO、UART、Timer、RS485 方向和初始化延时。
- `Public`：类型、板级常量、默认参数、超时和协议位置。

禁止下层包含或调用上层模块。中断服务函数只处理收发字节和系统计时，不解析协议、不访问传感器、不执行 Modbus 业务。

## 3. MTF 请求帧

请求严格固定为 15 字节：

```text
MTF:AB-CD-EFG\r\n
012345678901234
```

- 只接受真实的 `0x0D 0x0A`。
- 不兼容文本形式的四个字符 `\r\n`。
- AB、CD、EFG 所占字符都必须为 ASCII 十进制数字。
- 组帧使用固定数组和接收索引，不使用复杂解析状态机。
- 不完整帧 50 ms 超时；UART1 环形缓冲为 32 字节并带溢出标志。

请求结构只能包含：

```c
typedef struct
{
    uint8 command_code; // 本项目中保存从Pin1两个数字解析出的AB指令码
    uint16 parameter;   // 本项目中保存从工作值2三个数字解析出的EFG参数
} MtfRequest_t; // 本项目中保存一条已通过格式校验的MTF请求
```

协议说明、联调记录和代码统一使用 `command_code`（AB）、`target_code`（A）、
`function_code`（B）和 `parameter`（EFG）。`reserved_code` 是 CD 的字段名称，
只用于说明和格式校验；代码不得把它解析或保存到 `MtfRequest_t`，也不得传入 Control。

## 4. 字段规则

### 4.1 AB

AB 是唯一指令码，两个字符可解析为 `00~99` 的十进制数。格式层允许任意两位数字，业务层只接受本文定义的命令；未定义 AB 返回统一异常帧。

### 4.2 CD

**CD 只是固定两字节十进制占位符。**

- 只检查 `buffer[7]` 和 `buffer[8]` 是否为数字。
- 允许填写 `00~99`，正式命令建议使用 `00`。
- 不解析、不转换、不保存、不传给 Control。
- 不参与设备、通道、功能、参数、增益或 Modbus 地址判断。
- 请求结构体中禁止增加 CD 字段。
- 代码中禁止出现 CD 业务变量、`switch (cd)` 或 `if (cd == ...)`。

### 4.3 EFG

EFG 解析为 `000~999`，含义完全由 AB 决定。

## 5. TCS3400 命令

AB 十位为传感器编号 `1~4`，个位为操作编号：

| 个位 | 功能 | EFG |
|---:|---|---|
| 0 | 设置积分时间 | `003/028/051/103/178/712` |
| 1 | 读取 R | `000` |
| 2 | 读取 G | `000` |
| 3 | 读取 B | `000` |
| 4 | 读取 Clear | `000` |
| 5 | 读取 IR | `000` |
| 6 | 设置增益 | `001/004/016/064` |
| 7 | 保留，返回异常 | 不适用 |
| 8 | 保留，返回异常 | 不适用 |
| 9 | 读取 ID | `000` |

积分时间和增益必须单独设置。读取 RGBCIR 时沿用当前配置，禁止在读取命令中重新设置积分时间或增益。
`x7`、`x8` 不定义查询功能，任何 EFG 都返回统一异常帧。

## 6. 积分时间与增益

六档积分时间固定映射：

| EFG | ATIME | 周期 | 典型时间 | 最大计数 | 用途 |
|---|---:|---:|---:|---:|---|
| `003` | `0xFF` | 1 | 2.78 ms | 1024 | 高亮近距离、快速扫描，灵敏度最低 |
| `028` | `0xF6` | 10 | 27.8 ms | 10240 | 普通 LED、快速读取，固件默认积分档 |
| `051` | `0xEE` | 18 | 约 50.04 ms，协议标称 51 ms | 18432 | 中弱光，兼顾速度与灵敏度 |
| `103` | `0xDB` | 37 | 103 ms | 37888 | 弱光、反射检测 |
| `178` | `0xC0` | 64 | 178 ms | 65535 | 非常弱的 LED、高灵敏检测 |
| `712` | `0x00` | 256 | 712 ms | 65535 | 极暗或远距离检测，响应最慢且容易饱和 |

其他数值一律报错，不取整、不钳位、不自动选档。
`051` 是协议标称值；TCS3400 以典型 2.78 ms 为一个积分周期，18 个周期的硬件典型时间约为 50.04 ms。

四档增益固定映射：

| EFG | AGAIN | 增益 | 用途 |
|---|---:|---:|---|
| `001` | `0x00` | 1x | 高亮 LED、距离很近，降低饱和风险 |
| `004` | `0x01` | 4x | 普通 RGBW LED，固件默认增益档 |
| `016` | `0x02` | 16x | 较暗 LED、隔着外壳 |
| `064` | `0x03` | 64x | 极弱光或远距离检测，注意噪声和饱和 |

固件初始化四路传感器时必须实际写入并回读确认：

- 默认 ATIME：`0xF6`，典型积分时间 27.8 ms。
- 默认 AGAIN：`0x01`，增益 4x。
- 上位机未设置参数时，`x1~x5` 直接使用 27.8 ms、4x。
- `x0`、`x6` 设置成功后分别返回协议积分档位值和实际增益 Float。

调试时从 27.8 ms、4x 开始；LED 偏暗时先提高到 16x，仍偏暗时再逐档增加积分时间。数据接近 65535 时应降低增益或缩短积分时间。

芯片寄存器硬件复位值只是固件初始化前的短暂状态，不得写成项目默认配置。配置寄存器写入失败时不得更新软件状态。
运行期间设置 ATIME 或 AGAIN 失败时，不更新该路缓存，并按稳定 `main` 尝试回写最后一次成功值；回写失败时将该路标记为通信异常。
某一路上电初始化失败或运行中断线后，收到该路下一条有效命令时允许按缓存配置自动重试初始化；重试失败仍返回统一异常，不得返回缓存值。

## 7. 四路软件 I2C

| 总线 | SCL | SDA |
|---|---|---|
| `SOFT_I2C_BUS_1` | P0.4 | P5.2 |
| `SOFT_I2C_BUS_2` | P0.1 | P0.2 |
| `SOFT_I2C_BUS_3` | P4.5 | P4.6 |
| `SOFT_I2C_BUS_4` | P2.5 | P2.6 |

- TCS3400 7 位地址固定为 `0x39`。
- 四路共用一套软件 I2C 和一套 TCS3400 驱动。
- 所有接口必须显式携带 `SoftI2C_Bus_t`。
- 禁止使用“当前总线”全局变量和 sbit 函数指针。
- 每路独立保存最后一次成功的 ATIME、增益、通信状态、IR映射状态和等待时间。
- `x1/x2/x3/x4` 保留稳定 `main` 的积分和AVALID流程，但每条命令只访问指定的 R/G/B/Clear 通道。
- 16 位通道数据必须从偶数低字节寄存器开始一次连续读取两个字节，先低字节、后高字节；读取低字节时芯片会锁存对应高字节。

IR 读取必须执行稳定 `main` 流程：开启并回读确认 IR 映射、启动新积分、等待设定积分时间和 AVALID、读取 Clear 端口并暂存 IR、关闭映射、重新启动普通 Clear 积分、等待普通 Clear 的 AVALID 后再返回已保存的 IR 值。
本项目不增加 ASAT 饱和判断、平均值或滤波，调试人员通过实际计数范围选择积分时间和增益。

`x1~x5` 每条命令只执行一次完整采样；普通通道按需读取，IR仍执行完整映射和Clear恢复。I2C、寄存器回读、AVALID或IR恢复失败时直接返回一帧 `-1.0f`，不在内部自动重发。通道计数 `0` 和 `65535` 都可能是真实数据，不按数值判断失败。

## 8. 压力仪表

- 总线：UART2 + RS485，SN65HVD72 的 2 脚 `/RE` 与 3 脚 `DE` 并接，并通过上拉电阻连接到 P0.7。
- SN65HVD72 的 1 脚 `R` 和 4 脚 `D` 分别接有上拉电阻。
- P0.7 低电平：`DE=0`、`/RE=0`，驱动关闭并进入接收模式。
- P0.7 高电平：`DE=1`、`/RE=1`，接收关闭并进入发送模式。
- `GPIO_Init()` 先将 P0.7 锁存值拉低，再配置为推挽输出；固件运行期间空闲态保持接收。
- 协议：Modbus RTU，115200 bps、8N1。
- 地址范围：`001~247`。
- AB=`50`：普通读取指定地址压力，不执行限值比较、不改变 Y 输出。
- AB=`51`：清零指定地址仪表，不改变限值和 Y 输出。
- EFG 保存 Modbus 地址；总线最多连接四个仪表，但地址使用各仪表实际配置值，不限制为 `001~004`。
- 压力逻辑通道1~4分别固定控制Y1~Y4，MCU控制脚为P3.2、P3.3、P3.4、P5.0。
- MCU控制脚高电平使ULN2003导通并将外部Y端拉低；低电平使ULN2003截止并释放Y端。
- AB=`60/70/80/90`：设置第1~4组下限，EFG为整数压力值`000~999`。
- AB=`61/71/81/91`：设置第1~4组上限，EFG为整数压力值`000~999`。
- AB=`62/72/82/92`：读取EFG指定的实际Modbus地址，比较后分别更新Y1~Y4。
- 每路分别保存上下限值和有效标志；限值仅保存在RAM，复位后清除，不提供查询、取消、使能或地址绑定命令。
- 上下限比较统一使用实测压力绝对值，正负压力按相同大小处理；UART1返回值仍保留仪表原始正负号。
- 只设置下限时判断`|实测值|`小于下限，只设置上限时判断`|实测值|`大于上限，同时设置时任一越界即触发；等于限值不触发。
- 同时设置时必须满足下限小于上限；非法设置保留原配置和输出，成功设置后释放对应Y并等待下一次读取判断。
- 读取成功只更新命令指定的一路Y；没有设置限值时释放对应Y；Modbus失败时返回异常并保持原输出。
- 压力读取只用比较通道表示操作类型：`0`为普通读取，`1~4`为读取后更新对应Y，不再保存重复的比较使能标志。
- 原X1~X4输入跟随功能和`input_follow`模块已经删除，由`trigger_output`模块统一控制Y1~Y4。
- 实测值：功能码 `0x03`，寄存器 `0x0000`，一个有符号 16 位寄存器，大端传输。
- 小数位：功能码 `0x03`，寄存器 `0x0012`，按仪表手册只接受 `0~3`。
- 实际压力：`signed_raw / 10^decimal_places`，单位沿用仪表当前显示单位。
- 清零：功能码 `0x05`，线圈 `0x0000`，写入 `0xFF00`，校验响应回显后返回 `0.0f`。
- 每个 Modbus 子事务按稳定 `main` 只发送一次，响应超时为 200 ms。
- 响应长度按功能码和读取字节数动态确定；CRC、地址、功能码、长度、回显或UART2溢出异常直接结束本次事务。
- 读取和清零请求固定为8字节；读取单寄存器的正常响应为7字节，清零正常回显为8字节，异常响应为5字节。

## 9. 返回帧

正常响应固定 7 字节：

```text
3D B0 B1 B2 B3 0D 0A
```

中间四字节为小端 IEEE754 Float，不是 ASCII 文本。Keil C51 内存字节顺序与协议顺序不同，必须按现有 `MtfProtocol_BuildFloatFrame()` 显式重排。

异常响应仍使用正常 Float 帧，数值固定为 `-1.0f`：

```text
3D 00 00 80 BF 0D 0A
```

每条完整请求只返回一帧。控制器忙、格式错误、参数错误、I2C/Modbus失败或等待超时均返回Float `-1.0f`，主板不再判断 `FF FF FF FF`。

## 10. 编码要求

- 禁止 `goto`、动态内存、递归、无超时死循环和隐蔽指针技巧。
- 优先使用普通 `if`、`switch`、`for`、`while` 和小型静态辅助函数。
- `uint8`、`uint16`、`uint32`分别固定映射到Keil C51的8位、16位、32位无符号类型，属于本项目的明确宽度类型；不为名称统一而机械替换为`stdint.h`类型。
- 只在本模块使用的辅助函数必须声明为`static`，不得放入公共头文件；单一调用点的简单逻辑优先直接保留在调用函数中。
- 向调用方缓冲区复制可变长度数据时必须接收并检查缓冲容量；固定本地数组仍使用协议长度常量或`sizeof`传递容量。
- 仅在 TCS 采样、压力事务和 Modbus 收帧中使用小型枚举状态机；每个状态只完成一个明确步骤，不引入通用状态机框架。
- C 文件使用“内部定义”和“对外函数”分区。
- 每个 C 函数包含简洁的 `@brief`、`@param`、`@retval`。
- 项目自有 `.c/.h` 中每个 `#define` 宏都必须在同一行添加 `// ` 注释，包含头文件保护宏、寄存器地址、位掩码、长度、超时、重试次数和默认参数。
- 宏注释必须说明该值在本项目环境光、压力、MTF、串口、GPIO或状态机中的具体作用，不得只写“默认值”“长度”“超时”等无法对应业务的泛化文字。
- 每个结构体、联合体、枚举类型及其每个成员都必须使用 `// ` 注释，并明确写出“本项目中”，说明该类型服务于哪条项目流程，以及成员的数据来源、保存内容和使用位置。
- 修改结构体注释时不得改变成员类型、顺序、C51存储区域或结构体大小；需要增删成员时必须按功能变化单独评估，不能借补注释顺便改布局。
- 头文件函数声明使用行尾 `// ` 注释，说明该接口在本项目调用链中的用途；不得继续新增单行 `/* ... */` 接口注释。
- 复杂函数可在函数体开头用一条简短注释说明项目作用；简单函数不强制添加重复函数名或重复语句含义的入口注释。
- 函数内部注释重点说明硬件约束、状态转换原因、失败影响和协议字节顺序，不逐行翻译赋值、判断或循环语句。
- 复杂校验、连续业务步骤和异常恢复在代码块前使用一条 `// `，说明为什么要这样处理、失败后如何影响本项目结果或下一步操作。
- 注释不能只把C语句翻译成中文。例如不能只写“关闭中断”“索引加一”“启动定时器”，必须进一步说明关闭哪个项目链路的中断、索引用于哪类帧、定时器为哪些状态机提供时基。
- 函数内部不使用大段 `/* ... */` 描述完整业务流程；完整流程保留在设计文档中。
- `data`、`code`、`xdata` 等 C51 关键字不得作为变量名。
- 中断共享变量使用 `volatile`；多字节时基读取必须保证原子性。
- 驱动设置成功后才能更新缓存状态。

## 11. 工程和文档同步

- 所有 `.c` 必须加入正确的 Keil Group。
- Include Paths 必须包含 User、App、Control、Hardware、System、Public。
- 删除文件时同步移除 Keil 引用，禁止保留重复 ISR、函数或全局变量。
- 每次协议或硬件变更必须同步更新本文件和 `压力传感器及环境光的通信协议设计与实现.md`。
- 其他旧文档不属于本次维护范围。
- 提交前使用 C51 `WARNINGLEVEL(2)` 编译并链接到 `0 Error(s), 0 Warning(s)`，同时检查 DATA、XDATA 和 CODE 使用量。

- `main` 只保存已经完成编译和实机联调的正式可用版本，当前正式版本为 V1.3。
- `codex/v1.3-current-code` 是本次 V1.3 优化的来源分支，保留用于追溯 PR #6。

- 每次 Git 提交标题和正文必须使用中文。
- 提交标题使用 `功能：`、`修复：`、`文档：`、`重构：` 或 `版本：` 开头，直接说明本次目的。
- 提交正文必须列出修改了哪些功能、修改原因、对协议或硬件的影响、编译或联调结果，以及明确未上传的内容。
- PR 标题、PR 正文、合并标题、合并说明、Tag 注释和 Release 说明全部使用中文。
- 分支名使用简短 ASCII 技术名称，例如 `feature/v1.3`；中文用于提交和发布说明。

### 12.4 联调记录和构建产物

- `联调验证.md` 可以在本地持续更新，但其中的实机现象、测试结果和问题记录默认不得上传。
- 只有用户明确指定需要公开的联调说明时，才可以从本地记录中整理非敏感内容后单独提交。
- Keil Objects、Listings、HEX、OBJ、LST、构建日志和用户界面配置不得纳入提交。
- 每次代码上传前应完成 Keil 编译；无法编译时必须在中文提交说明和最终报告中明确写出原因。
